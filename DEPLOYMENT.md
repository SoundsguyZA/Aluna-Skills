# Deployment blueprint

## Customer-specific layer (private)
The customer owns their profile, business records, projects, email, calendar and permissions. Configure their own account with short global custom instructions. Keep projects separated by business area. No shared customer memories or shared credentials.

## Shared core
Truth, red-team, humanizer, verification, adaptive learning and executive operations. Property edition adds commercial outcomes and site survey/proposal. Source version: Aluna-Skills main commit d3e9d528582fa8df56c02b756820150e297dacb6 (seven unchanged skills); executive operations is newly authored for this release.

## Setup
Start with native chat and instructions. Enable memory only with customer consent and verify its actual controls. Treat private project records as source of truth rather than relying on remembered details alone. Connect only approved apps where supported. For external MCP, register a clean independent repo and verify the account can attach it. A public skills repository is never an appropriate client datastore.

## Commercial offering
One-time onboarding and workflow configuration; optional training and support; optional managed updates and integration service. Define deliverables, access boundaries, cost limits, support and customer ownership before commercial commitments. No pricing assumptions or performance guarantees.

## Updates
Pin a release version; run acceptance scenarios and compare baseline before promoting. Use reviewed changes from upstream; verify the downstream tree and MCP retrieval. Roll back to previous known-good release if a regression occurs. The future Evolution Engine is separate from this release and is not needed to start.
